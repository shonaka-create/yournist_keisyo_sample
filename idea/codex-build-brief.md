## 0. ゴールと成果物

- **目的**：医薬品卸売業に「業務の属人化解消・標準化・事業承継の“業務引き継ぎ”」を売る B2B LP。
- **成果物**：**静的 HTML / CSS / （必要最小限の）JS**。
  - 理由：後工程で WordPress(Cocoon子テーマ) へ移植するため（`static-to-wp-cocoon` パイプライン前提）。フレームワーク・ビルドツールは使わず、素の HTML/CSS で完結させる。
- **ディレクトリ**：`site/` 配下。`site/index.html`、`site/assets/css/style.css`（`design/tokens.css` を `@import` か先頭にインライン）、`site/assets/img/`。
- **レスポンシブ必須**（375 / 768 / 1280 で崩れないこと）。

## 1. デザイン規範（tokens）

`design/tokens.css` の CSS変数をそのまま使う。要点：
- プライマリ `--color-primary:#1e49e2`（リンク・ボタン）／深み `--color-primary-deep:#00338d`（ホバー・見出しアクセント）／本文 `--color-ink:#0c233c`／面 `--color-surface:#f5f6fa`。
- 本文 `Inter, "Noto Sans JP"`、見出し太め(700)。字間広めの英字アイブロウ可(`--tracking-caps`)。
- 角丸 `--radius:6px`、余白は tokens のスケール、gap 8px 基調。
- **世界観**：堅実・清潔・信頼（医療/インフラの安心感）。派手な演出・回路/ロボット等の“テック/AI感”は禁止。
- 写真：現場が滞りなく回っている安心感。人物は誠実・実直な印象。

## 3. トップページ 確定コピー（このまま実装）

### (1) ヘッダー
- ロゴ：テキスト「**事業承継レスキュー**」＋小さく「by YOURNIST」／ナビ：サービス｜進め方｜料金｜会社情報｜**［無料診断］ボタン**（primary）

### (2) ヒーロー（FV＝課題ダイレクト）
- アイブロウ：`業務の属人化を解消し、標準化・事業承継へ`
- **H1：その受発注、あの人が辞めても回りますか。**
- サブ：得意先ごとの価格も、急配の判断も、返品の段取りも——医薬品卸の**属人化した業務**を読み解いて**標準化**。事業承継・世代交代の前に、誰でも引き継げる状態にします。
- CTA（第一）：**無料で引き継ぎリスクを診断する** ／ 第二：サービスを見る
- ビジュアル：清潔な物流/オフィスの落ち着いた写真＋青のアクセント。

### (3) 共感（こんなお悩みありませんか）※FAQ構造化データにも流用
- 「この価格計算、○○さんしか分からない」
- 「薬価改定のたびに手作業で直している」
- 「急配できるかは、あの人に聞かないと判断できない」
- 「返品・回収の段取りが人によってバラバラ」
- 「担当が辞めたら、月末処理が止まる気がする」

### (4) 医薬品卸売で進む「業務の属人化」というリスク（H2・SEO本文）
- リード：医薬品卸売の現場では、受発注・配送・問い合わせの判断が特定のベテランに集中しがちです。属人化したまま退職・世代交代が起きると、**供給が止まるリスク**に直結します。
- 3つの損失：①請求ミス/漏れ ②欠品・過剰在庫 ③月末・回収対応の停止

### (5) 私たちがすること：属人化を解消する3ステップ（H2）
1. **診る**：どの業務が“その人しか分からない”状態かを洗い出す
2. **標準化する**：受発注・配送・問い合わせのルールと手順を文書化・テスト化
3. **引き継ぐ**：次の担当者・後継者が読んで動ける状態で納品
- ※コピーに「AI/自動化/DX」を使わない。「読み解く／棚卸し／見える化／標準化」で統一。

### (6) 業務3区分（カード3枚 H2：受発注・配送・問い合わせを標準化して引き継ぐ）
- **受発注**：得意先別の掛率・薬価改定・未妥結が属人化 → 誰でも同じ請求が出る状態へ。［詳しく→/service/order/］
- **配送**：急配判断・期限/ロット/温度帯・回収対応がベテラン頼み → 止めない/間違えない手順へ。［→/service/delivery/］
- **問い合わせ**：在庫・納期・欠品対応が集中 → 新人でも一次対応できる状態へ。［→/service/support/］

### (7) なぜ医薬品卸に特化するのか
- 薬は止められない社会インフラ。属人化は“供給が止まるリスク”に直結する。
- 業界の商習慣（掛率・薬価・温度帯・回収）を分かった上で引き継ぎを設計する。

### (8) 事業承継・世代交代の前にやるべき「業務の棚卸し」（H2・SEO）
- 財務や株式だけでなく、**実務（受注〜請求、在庫、配送、問い合わせ）の引き継ぎ**が本当の事業承継。ベテランが辞める前が最も安く、確実。

### (9) 進め方（安心設計）
- 本番環境は原則さわらない（コピーで作業）／機密は預からず限定環境で確認／最終判断は必ず御社（勝手にシステムを止めない）。

### (10) 料金の入口
- **引き継ぎリスク診断** 5〜10営業日／30〜80万円：重要業務と“止まると困る箇所”を可視化
- **引き継ぎ整備（標準化）** 4〜8週間／120〜300万円：ルール・手順・テスト・復旧手順を整備
- ※本格移行・月額運用は診断後に個別提案

### (11) 最終CTA
- H2：**「あの人が辞める前」が、いちばん安く済みます。**
- ボタン：無料で引き継ぎリスクを診断する

### (12) フッター
- サービス名「事業承継レスキュー」／運営：**YOURNIST株式会社**
- お問い合わせ：**yournist@gmail.com**
- リンク：会社情報｜情報の取り扱い｜プライバシー｜お問い合わせ

### (13) お問い合わせ / 診断申込（/contact/）
- フォーム項目：会社名・お名前・メール・電話（任意）・相談内容
- 送信先メール：**yournist@gmail.com**（静的サイト段階は `mailto:yournist@gmail.com` かフォーム→メール送信。WP移植時にContact Form 7等へ置換）

- 実装制約：後で WordPress(Cocoon) へ移植するため **素のHTML/CSS＋最小JS** を維持。CSSは `assets/css/style.css` に集約、`tokens.css` は変更しない。重いJS・ビルドツール・フレームワーク禁止。
- **仕上げ出力**：①変更点の要約 ②追加/変更したSVGファイル一覧 ③トークン外の色を使っていないことの確認 ④「次に用意すべき実写素材リスト」（ヒーロー差し替え候補など）。

> ※実行後チェック：トークン外の色混入がないか、H1が1つか、FVコピーが上記どおりか、contactのmailtoが生きているかを確認する。

### 5-C. フル実装（骨組み不要で一気に作る場合）

> 医薬品卸売業向けの B2B ランディングページを、素の HTML/CSS（＋最小限のJS）で実装してください。
> ビルドツール・フレームワークは使わず、後で WordPress(Cocoon) に移植できる静的サイトとして `site/` 配下に作ります。
> デザイントークンは同梱の `design/tokens.css` を読み込み、その CSS変数（色 #1e49e2/#00338d/#0c233c/#f5f6fa、フォント Inter+Noto Sans JP、角丸6px、余白スケール）だけで配色・余白・タイポを構成してください。世界観は「堅実・清潔・信頼（医療/インフラの安心感）」で、テック/AI/ロボット的な演出は禁止。
> ページ構成・各セクションの見出しと本文は `idea/codex-build-brief.md` の §2〜§4 の確定コピーをそのまま使用。まず `site/index.html` と `site/contact/` を完成させ、375/768/1280 でレスポンシブに崩れないこと。SEO（title/meta/H構造/構造化データ/OGP/sitemap）は §4 の指示に従うこと。

## 6. お役立ち記事3本（構成）— 売り込みではなく解説読み物

方針：SEOキーワードに関する**課題と対策を中立・実務目線で解説**。売り込みは末尾のCTAのみ。
共通構成：`導入（あるある課題）→ 原因 → 放置するリスク → 対策ステップ → チェックリスト → まとめ → 関連記事＋控えめな診断導線`。
各記事：H1は1つ、`Article`/`BreadcrumbList` 構造化データ、想定読了3〜5分（2,000〜3,500字目安）、見出しにキーワードを自然に含める。「AI・自動化・DX」は見出しに使わない。

1. **`/column/attribution/` 業務の属人化とは？原因・リスクと医薬品卸での解消ステップ**
   - 狙う語：業務属人化 / 属人化 解消 / 属人化 標準化
   - 骨子：属人化の定義 → なぜ卸の受発注・配送・問い合わせで起きるか → 退職・世代交代時のリスク（供給停止・請求ミス）→ 解消の3ステップ（診る/標準化/引き継ぐ）→ 自社チェックリスト → まとめ

2. **`/column/standardization/` 業務標準化の進め方 — 受発注・配送・問い合わせを止めない仕組み**
   - 狙う語：業務標準化 / 標準化 進め方 / マニュアル化・手順書
   - 骨子：標準化とは（マニュアル化との違い）→ 進め方5ステップ（現状把握→ルール抽出→手順書→テスト→運用）→ 業務区分別のコツ → 失敗パターン → チェックリスト → まとめ

3. **`/column/succession/` 事業承継で見落とされがちな「業務の引き継ぎ」— 世代交代前のチェックリスト**
   - 狙う語：事業承継 / 事業承継 業務 引き継ぎ / 後継者 引き継ぎ
   - 骨子：財務・株式だけでは承継は完了しない → 実務（受注〜請求・在庫・配送）の属人化が統合を止める → いつ着手すべきか（辞める前が最安）→ 引き継ぎチェックリスト → まとめ

> 各記事末尾のCTA例（控えめ）：「自社の属人化リスクを把握したい方へ → 無料の引き継ぎリスク診断」
